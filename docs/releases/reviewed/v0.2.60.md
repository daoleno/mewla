Mewla no longer edits your Codex settings or reads Chrome's storage, attachments can only come from Mewla's uploads, and the session list follows a hidden or shown session at once. Update the phone app together with the daemon. **If you use the browser tools, you will be asked for the Playwright extension's key once more.**

## New

- **Mewla trusts a Worker's folder for Codex on Codex's command line, not in your settings.** It used to write the folder into `~/.codex/config.toml` and keep it there. Your Codex config is left alone now; Claude Code has no way to do this per launch, so for Claude Workers Mewla still sets that one folder in Claude's own config.
- **Mewla no longer reads Chrome's storage to find the Playwright extension's key.** The extension shows the key on its own page; tap **Open it** in Settings, copy the key, and either run `mewla agent-use key` on the computer and paste it, or tap **Paste key** on the phone. If Mewla had found your key by itself before, it now asks once, and then keeps it.
- **A turn that fails with an error the agent didn't classify is tried twice more, then goes to Brain.** Mewla now decides only from the agent's own error code and HTTP status and never from the wording of the message. Before, it also matched words such as "try again" and "额度不足".

## Fixed

- **A message can only attach files that are in Mewla's uploads.** A path anywhere else on the computer, one that climbs out with `..`, or a link pointing out of the folder is refused before an agent sees it. Writing the attachment tag into the message text no longer attaches anything either.
- **A session that becomes hidden leaves the list, and one that is shown again comes back, right away.** The list used to catch up only on its once-a-minute check.
- **Codex's thread database honours `CODEX_HOME`** and is opened read-only.
- **Stats name a Claude project by the folder it ran in.** A folder such as `mewla-cat-lab` was shown as `lab`. Sessions that can't be read are now reported instead of quietly lowering the totals.
- **Resuming a delegated Codex Worker no longer fails as ambiguous** because of its hook-trust flag.
