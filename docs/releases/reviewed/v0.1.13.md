## Highlights since v0.1.12

- Plugins and Skills management now show the current server, clearer account and inventory states, and focused actions. The navigation drawer groups destinations, labels Model Providers consistently, and honors reduced motion and cancelled drag gestures.
- Persistent Browser resources support reusable server-owned profiles and managed Codex/Claude session attachment. New browsers are shared with same-server Agents by default, with one input owner and explicit takeover. The Browser navigation entry is temporarily hidden; its route and server resources remain available.
- Plugins now provides service-first onboarding with official browser authorization, reviewed read/write capability groups, and server-owned connected accounts for Brain and Workers. Custom MCP and OpenAPI services retain explicit endpoint, network-trust, and tool-permission boundaries.
- Native authorization returns remain bound to the original server across server switches. Resume, cancellation, and retry states are clearer, and older native clients can open the official authorization page without crashing on an unavailable browser module.
- GitHub device authorization preserves expiring access tokens and rotating refresh tokens. Daemon builds consume reviewed public publisher metadata; provider registration and real account consent remain separate prerequisites.
- Brain recovers missing host sessions throughout the daemon lifetime using host-removal events. Cursor worker detection uses the executable identity so selecting a Claude model does not misclassify the worker.
- Remote Desk and its dedicated Android/iOS and daemon runtimes have been retired, including obsolete desktop pairing guidance.

## Known limitations

- Persistent Browser remains a candidate capability. Its current runtime adapter requires Linux, installed Chrome/Chromium and agent-browser, and an already unlocked Secret Service wallet. Remote page pixels do not include native browser chrome or device-bound passkeys; Google/MFA acceptance and protection from unrestricted same-UID shells are not established. Existing Agent attachments are not restored after a daemon restart.
- First-time built-in connections depend on each provider's publisher readiness and the user's real account consent. Protocol tests, public-client build wiring, and successful discovery do not prove a live provider grant. Slack/Google publisher provisioning remains incomplete; Linear/Notion account consent and granted operations remain unverified.
- iOS Preview delivery requires successful exact-tag archive/export, App Store Connect upload and processing, and Apple's Beta App Review. The previous v0.1.12 upload was rejected with an App Store Connect agreement HTTP 403; the new release must establish its own outcome before claiming TestFlight availability.
- Android is distributed as a signed arm64 APK without a Play Store package; installation may require allowing unknown sources.
