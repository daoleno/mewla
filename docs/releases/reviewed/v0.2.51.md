Codex sessions started from Mewla are now followed through Codex's own channel instead of its screen: Mewla knows the conversation from the first moment, sees each turn start and finish, answers permission prompts without typing, and sends your messages with a receipt.

## New

- **Codex Workers report what they are doing.** A Codex session started by Mewla runs with its own local control channel. Mewla learns the conversation id the moment Codex creates it, sees a turn begin and end, and shows Codex's own error (a rate limit, a refused request) instead of guessing from the screen. Helper conversations Codex starts for itself are ignored.
- **Codex permission prompts are answered without keystrokes.** `mewla worker approvals` lists a waiting command or file change, and `mewla worker approve` allows or declines it straight through Codex.
- **Messages to a Codex session you started are sent to Codex directly,** with a receipt that Codex echoes back, rather than pasted into the terminal and read back. A message Codex refuses is reported as not sent, and one whose outcome is unknown is never sent twice.

## Fixed

- **A Claude hook is accepted only from the session Mewla launched.** A hook event carrying another conversation's id is rejected, and a permission decision only answers a request from the conversation that asked. A Worker still follows its own `/clear`, `/compact` and resume.
- **Codex conversations are found when the session has helper threads.** A thread listing the newer Codex sends in a different shape no longer fails the lookup.
