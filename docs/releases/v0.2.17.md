# Mewla 0.2.17

Pairing your phone works reliably, and Mewla on a Mac started at login runs Brain and Terminal again. Update the app to 0.2.17 as well.

## New

- The remote access pairing QR code now fits an 80-column terminal. Scan it with app 0.2.17 or later; `mewla pair --details` still shows the link older apps can read.
- `mewla web` opens Mewla in this computer's browser, already paired, and lists the addresses that work in a browser. Over SSH or without a display it only prints them. Opening a pairing link for a computer the app already saved no longer asks again what it may access.
- If more than one agent CLI is ready on first run, `mewla` asks which one Brain uses (Claude Code first). With one agent it still picks it without asking; change it later with `mewla brain use`.
- From 0.2.17 on, `mewla update` finds new versions without the GitHub API, so it doesn't hit rate limits. It offers only stable releases.

## Fixed

- Pairing could put the phone's own address (`https://127.0.0.1:…`) in the QR code instead of this computer's. It no longer does, and addresses learned that way are forgotten.
- Scanning or retrying the same pairing code from the same phone now finishes pairing instead of failing with a used code. If the computer already trusts the phone, the app connects.
- After a pairing error, the scanner waits until you dismiss it instead of submitting the spent code again. Remote pairing errors say what went wrong (computer unreachable, code already used) instead of naming internal ports.
- `mewla pair` with remote access no longer fails with a bare "main: EOF" when the sign-in grant is slow to refresh; a failure now names the step that failed.
- Removing a computer in the app also asks that computer to forget this phone.
- On a Mac with `mewla boot install`, Brain, Terminal and new shells could not open. They work again, and Codex sessions on a Mac are recognized.
- A service started at login no longer writes a pairing code to its log, and the Mac log `~/.mewla/logs/launchd.log` is readable only by you. Run `mewla pair` to show a code.
- Onlora's `update_asset` tool is grouped with its other write tools.

## Get it

- **Already installed?** Run `mewla update` on your computer, and install the new APK on Android.
- **New here?** `curl -fsSL https://mewla.ai/install.sh | sh` picks the right file for you. See [Install](https://mewla.ai/docs/install/).
- **Mac (Apple Silicon):** `mewla-darwin-arm64.tar.gz`. Needs `tmux` (`brew install tmux`).
- **Linux x64:** `mewla-linux-amd64.tar.gz`
- **Linux ARM:** `mewla-linux-arm64.tar.gz`
- **Android:** `mewla-android-arm64-v0.2.17.apk`. Android asks you to allow installs from unknown sources.
- **iPhone:** [Mewla Preview on TestFlight](https://testflight.apple.com/join/nMQheDCE)

All changes: [v0.2.16...v0.2.17](https://github.com/daoleno/mewla/compare/v0.2.16...v0.2.17)
