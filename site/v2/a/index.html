Brain

One goal in. Reviewed work out.

Brain is an agent of its own, running on your computer. It holds the goal and keeps going, so you never relay messages between agents or check on each one.

  1. 1

    You say it once.

    Type a goal to Brain on the phone, or send it from Telegram. Then put the phone away.

  2. 2

    Each part becomes durable Work.

    Brain records every part as Work, with its attempts, wake timers and review state. Work survives restarts, and Brain doesn’t poll: Workers report back and timers wake it when something is due.

  3. 3

    You set the routing in plain Markdown.

    Before each spawn, Brain reads routing.md to choose the executor, model and reasoning level for each part. Tell Brain a preference and it rewrites the line.

    # routing.md (example)
- UI and copy: claude, high reasoning
- Go daemon and tests: codex
- Quick lookups: pi
  4. 4

    Workers are ordinary Sessions.

    Every Worker is a normal agent Session on your computer, running in tmux. Open any of them to read along, answer a question or take over.

  5. 5

    Nothing is done until it’s reviewed.

    Brain reads each result and decides the next step. Only Brain or you can mark Work done. A Worker that goes missing shows up as Needs review, not as a success.

Everything in the app

One butler, a house full of tools.

Brain keeps

  • Memory you can read

    current.md, profile.md, memory.md and a worklog, as plain files in its workspace.

  • Switch the host, keep the thread

    zen brain use codex moves Brain itself to another agent client, thread intact.

  • Calendar Beta

    Events, reminders and deadlines. A scheduled action runs as visible Work and posts its result back.

  • Telegram Beta

    A second channel to the same Brain, for when the app isn’t open.

  • Plugins Preview

    Linear, Notion, GitHub, Slack, Google Workspace, or your own MCP and OpenAPI servers. Reading is on by default; writing is a separate switch.

  • Resources

    CPU, memory, disk and pressure, each process attributed to a Worker, Brain, Docker or you. Brain is told when the machine runs short.

Install

Three steps from your terminal to your pocket.

  1. Install the daemon

    curl -fsSL https://raw.githubusercontent.com/daoleno/zen/main/install.sh | sh

    Checksum-verified, no sudo, no telemetry. Then run zen doctor to check the host.

  2. Start it on your network

    zen --lan

    On a trusted private network. Away from home, use Tailscale: zen -addr "$(tailscale ip -4):9876".

  3. Scan the code

    Open the app and scan the QR code zen prints. Pair once, then open Brain.

Yours

One owner, on your own machine.

Zen serves one person. The daemon has an Ed25519 identity, and a phone enrolls once with a short-lived pairing code, then signs every request. Repositories, credentials and agent state stay on your computer. Paired phones see what you open; model providers see what your agents send them.

Security and privacy · Report a vulnerability

Read this before you run it on a work machine

Several defaults bypass approval prompts so agents can work unattended: cursor-agent --force --sandbox disabled, grok --permission-mode bypassPermissions, and Brain-delegated Codex adds --dangerously-bypass-approvals-and-sandbox. On machines with secrets or production access, use the safe profile in executors.example.toml.
